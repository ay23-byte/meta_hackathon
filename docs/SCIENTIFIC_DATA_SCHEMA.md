# Scientific result and context schema

`result_schema.build_result()` remains the source of deterministic values and creates schema version `2.0`. Its source block records file name, row count, detected delimiter/encoding and source-byte SHA-256 where available. `roles`, `cleaning`, `statistics`, `correlation`, `outliers`, `fit`, `model_comparison`, `domain`, `visualizations`, `warnings` and optional `ai` retain their existing meanings. A hash identifies bytes, not the truth of their provenance.

When the user enables offline research notes, `general_app.py` adds an optional `research` object. Existing consumers must tolerate its absence. It includes `context` (bounded user-supplied metadata, explanation level and confirmation flag), `theory` and `reliability` notes, and `chapter`. Chapter status is `context_needed` or `conditional_user_confirmed`; sections and symbols are deterministic text; missing fields are explicit. `derived`, when available, is a model-based resistance in ohms with conversion factor and pointer to `fit.parameters.slope` and user-selected units. It must not replace the fit parameter. `completeness` records missing/conditional verification, including unverified literature. Changing research context changes the existing session fingerprint and invalidates cached reports.

Live or mock AI remains separately labelled and validated in `ai`; the optional research context is not automatically included in the provider context. JSON serialization uses existing non-finite handling, and Markdown escapes untrusted user text. The new field is additive: no migration or schema-version bump was made. This is an application data contract, not a formal external scientific metadata standard. More extensive evidence identifiers, uploaded documents, full theory provenance and validated citations are not yet implemented. Do not include secrets or confidential information in exportable user metadata.
